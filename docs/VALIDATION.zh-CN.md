## 原生新用户流程

专用宿主使用正式界面和清理引擎，应用记录为空并与个人资料隔离。实际操作验证：

1. 首次按钮明确为扫描常用位置，说明下载、缓存和日志、1 MB 起。
2. 临时目录拒绝读取后，自动出现文件访问助手；提供选择文件夹、前往系统设置、重新检查，容量标为尚未读取。
3. 仍被拒绝时重查不误报成功，关闭助手后保留未读入口；系统设置按钮正确到达完全磁盘访问，没有改动授权开关。
4. 恢复临时目录权限后重开，自动按原范围补扫，7 项临时文件出现且都没有默认勾选。
5. 添加推荐项只选择旧安装包和已识别 pip 缓存；两项项目、视频和未知缓存仍未选择。footage 名称的视频正确归入视频素材。
6. 手动全选、取消项目分组、取消未知缓存、进入文件分组及返回均有效；最终复核取消安装包整组。
7. 混合批次明确显示整批 2 项及容量，并列出其中 1 项需自行确认的内容；未勾选确认时不能移动，返回复核后旧确认失效。
8. 视频和 pip 缓存实际进入 macOS 废纸篓。原视频位置放入临时冲突文件后，对应恢复按钮禁用，先恢复缓存不会覆盖冲突文件。
9. 仅移走生成的冲突文件后，重新检查可恢复视频。**全部 7 项原文件哈希一致**，两项操作日志最终已恢复，项目从未被移动。
10. 原生选择器选定文件夹后只扫描该范围。最终生产构建安装回原位置，可打开原有记录；英文状态修复已在生产构建观察，最后恢复跟随系统语言。

用户原有清理历史、忽略偏好与日志事件内容未变。生产应用正常启动可能更新 SQLite 页头计数器，不声称重开后数据库整文件字节不变。

## 验证边界

- 拒绝和恢复使用生成目录真实的 POSIX 读权限，macOS TCC 授权未改动；不能等同于全新系统账号首次授予完全磁盘访问。
- 原公开程序代码也用于隔离主目录的首次扫描。系统废纸篓位置不跟随这种重定向，因此该设置的身份校验拒绝被记为测试限制；实际清理恢复使用普通系统废纸篓解析的专用宿主，没有放宽路径校验。
- 本机运行不能替代另一台 Mac 默认 Gatekeeper 首次启动验收。原有系统安全评估设置未改动；只读分发检查仍报告缺少公证票据。
- 实机 Apple Silicon / macOS 27.2；编译最低 macOS 14。macOS 14 实机、另一台 Mac 的首次启动及授权、真实外置盘拔插仍待验证。
- 固定本机签名身份、Hardened Runtime 保持不变，**暂无 Developer ID 签名或 Apple 公证**。保留 1.8.3 应用、标签与发布附件，继续作为 Beta。
